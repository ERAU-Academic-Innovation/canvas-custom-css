# Canvas Custom CSS — ERAU Academic Innovation

Custom CSS stylesheets used to theme Embry-Riddle Worldwide online courses. A single `@import` line is uploaded to the Canvas LMS Theme Editor, pulling in `custom-themes.css` — a single self-contained bundle with every theme's CSS already inlined (no further `@import`s) — which allows instructional designers to apply one of several Embry-Riddle themes with branded color palettes and layout tweaks on top of Cidilabs DesignPLUS.

**Scope:** currently installed only at the Worldwide (WW) Canvas subaccount.

## Repository Contents

| File(s) | Purpose |
|---|---|
| `custom-themes.css` | **Auto-generated production bundle.** Contains the actual, inlined CSS of every theme — no `@import`s. Generated by [`build.py`](#build-process); don't hand-edit it. |
| `custom-themes.manifest.css` | Source list of every theme file, in load order, as `@import` lines. This is what you edit to add/remove/reorder a theme. |
| `custom-themes-dev.css` | Development bundle. Still `@import`s each theme individually via GitHub Pages instead of the CDN, so changes show up without waiting for a cache to purge or a rebuild. |
| `theme-erau-base.css` | Core/base stylesheet for all ERAU branded themes below. Required as a foundation for every theme variant. |
| `theme-erau-solid-<color>.css`<br>`theme-erau-solid-<color>-<accent>.css` | **Solid themes.** Single brand color (`beyond`, `black`, `unrivaled`) with an optional accent variant (`altitude`, `sunrise`; `black` also has an `unrivaled` accent). One exception runs the other way: `solid-sunrise-unrivaled`/`solid-sunrise-beyond`/`solid-sunrise-black` and `solid-grey-unrivaled`/`solid-grey-beyond`/`solid-grey-black` use `sunrise`/`grey` as the background with `unrivaled`/`beyond`/`black` as their accent. Prefixed with `solid-` (unlike the internal CSS class names, which are unchanged) so these sort together in a file listing, alongside `gradient-`/`wing-`. |
| `theme-erau-gradient-<color1>-<color2>-<accent>.css` | **Gradient themes.** Soft blend between two brand colors, in the direction `<color1>` → `<color2>` (e.g. `beyond-black`, `black-unrivaled`, `sunrise-grey`, `altitude-grey`), with an accent variant (`sunrise`, `altitude`, `grey`; `sunrise-grey`/`grey-sunrise` and `altitude-grey`/`grey-altitude` use `unrivaled`, `beyond`, or `black`). |
| `theme-erau-wing-<color1>-<color2>-<accent>.css` | **Wing themes.** Hard-edge split (no gradient) between two brand colors, same direction/accent naming as the gradient themes above. |

## DesignPLUS Course Setup

Instructional designers pick a theme in the DesignPLUS "ERAU Themes" content block by pasting a theme's classes into the course's settings course. [`docs/designplus-themes.md`](docs/designplus-themes.md) has a copy-pasteable table for every theme, grouped by primary color, so this can be done straight from GitHub's rendered markdown without touching HTML.

## Usage

These stylesheets are loaded through Canvas's Theme Editor, not linked directly from GitHub.

### Production

Add the following line to the CSS uploaded to the LMS:

```css
@import url(https://cdn.jsdelivr.net/gh/ERAU-Academic-Innovation/canvas-custom-css/custom-themes.css);
```

`custom-themes.css` has every theme's CSS inlined directly (see [Build process](#build-process) below), so this is the **only** request the LMS makes for theming — the browser no longer has to fetch, parse, and wait on 40+ separate `@import`ed files in serial before the page can finish rendering.

This still caches on jsDelivr and does not reflect new commits immediately (see [CDN caching](#cdn-caching-jsdelivr) below).

### Development

Upload `custom-themes-dev.css` itself to the LMS. It references the same themes via GitHub Pages instead of the CDN, so changes to this repo show up faster for testing. It's deliberately left as one `@import` per theme (not bundled) so an edit to a single `theme-erau-*.css` file is visible without running a build.

## Build process

`custom-themes.css` is generated, not hand-written. The source of truth is `custom-themes.manifest.css`, which lists every theme file (in load order) as an `@import`. [`build.py`](build.py) reads that manifest and inlines each referenced `theme-erau-*.css` file's actual content in place of its `@import`, producing the single self-contained `custom-themes.css`.

To add, remove, or reorder a theme:

1. Edit `custom-themes.manifest.css` (and/or add the new `theme-erau-*.css` file).
2. Run:
   ```bash
   python3 build.py
   ```
3. Commit the updated `custom-themes.css` alongside your change.

Step 2–3 also happen automatically: a GitHub Action ([`.github/workflows/build-custom-themes.yml`](.github/workflows/build-custom-themes.yml)) runs `build.py` and pushes the regenerated `custom-themes.css` whenever a `theme-erau-*.css` file, the manifest, or `build.py` itself changes on `main`. So even if you forget step 2, `main` self-heals within a minute of your push — you generally only need to touch the manifest and theme files.

### CDN caching (jsDelivr)

The production import above has no version pin (no `@main`, no tag), so per [jsDelivr's own docs](https://github.com/jsdelivr/jsdelivr#the-file-you-are-linking-doesnt-download), an unpinned URL resolves to the latest tagged release if one exists, otherwise it falls back to the repo's default branch — which is what happens here, since this repo has no git tags. jsDelivr itself flags this pattern ("omit the version completely") as **not recommended for production usage**, mainly because of caching:

- **Branch-referenced files** (our case) are cached on jsDelivr's CDN for **12 hours** before it re-checks GitHub for changes.
- **Tagged releases / commit hashes** are cached effectively forever (1-year headers, permanently stored in S3) — immutable, but predictable.
- **`@latest`/version-aliased URLs** are cached for **7 days**.

So after merging a change to `main`, production Canvas courses can take **up to 12 hours** to pick it up.

**To force an update sooner:** purge the specific file by swapping `cdn.` for `purge.` in its URL and requesting it (e.g. in a browser or via `curl`):

```
https://purge.jsdelivr.net/gh/ERAU-Academic-Innovation/canvas-custom-css/custom-themes.css
```

Since `custom-themes.css` is now self-contained (no nested `@import`s), purging that one URL is sufficient — you don't need to separately purge individual `theme-erau-*.css` files for production to pick up a change.

**Alternative:** cut a git tag/release and pin the production import to it (e.g. `.../canvas-custom-css@v1.2.0/custom-themes.css`) for immutable, predictable delivery. The trade-off is that production won't pick up new commits at all until the LMS import line is manually updated to point at a new tag.
